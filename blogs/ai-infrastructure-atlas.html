      1Learning path of running local AI

      The core path for running AI privately: make an open-weight model fit, run fast, serve many users, follow the rules, and justify its cost.

      Lab 0Do the memory math before touching hardware30 min
      2 · Inference mechanics

      Predict whether a model fits and how many users it can serve, so every later lab has a number to check against.

      1. Download the model's config file. Any open model works; this path uses Qwen2.5-7B-Instruct throughout so the numbers stay comparable.
        curl -LO https://huggingface.co/Qwen/Qwen2.5-7B-Instruct/resolve/main/config.json
      2. Save this script as fit.py. It uses only the Python standard library.
        # fit.py: will the model fit, and how many users can share the GPU?
# usage: python3 fit.py config.json <params, billions> <bytes per weight> <GPU GB> <context>
import json, sys
cfg = json.load(open(sys.argv[1]))
params_b, bpw, gpu_gb, ctx = float(sys.argv[2]), float(sys.argv[3]), float(sys.argv[4]), int(sys.argv[5])
layers = cfg["num_hidden_layers"]
kv_heads = cfg.get("num_key_value_heads", cfg["num_attention_heads"])
head_dim = cfg.get("head_dim") or cfg["hidden_size"] // cfg["num_attention_heads"]
kv_per_token = 2 * layers * kv_heads * head_dim * 2          # K and V, 16-bit cache
weights = params_b * 1e9 * bpw
budget = max(gpu_gb * 1e9 * 0.9 - weights - 1.5e9, 0)       # 10% headroom, ~1.5 GB runtime
print(f"weights {weights/1e9:.1f} GB | KV cache {kv_per_token/1024:.0f} KiB per token")
print(f"KV budget {budget/1e9:.1f} GB = {int(budget // kv_per_token):,} tokens "
      f"= {int(budget // (kv_per_token * ctx))} users at {ctx:,} tokens each")
      3. Predict a 24 GB GPU in 16-bit weights and in 4-bit weights, at 8,192 tokens of context.
        python3 fit.py config.json 7.6 2 24 8192     # BF16
python3 fit.py config.json 7.6 0.5 24 8192   # 4-bit

      Done when You have a written prediction: weights in GB, KV cache per token (about 56 KiB for this model), and users per GPU. Labs 4 and 7 check it.

      Lab 2See prefill and decode as two different costs1 h
      2 · Inference mechanics12 · Benchmarking & cost

      Measure the two phases yourself: long prompts make the first token slow, while decode speed hardly changes.

      1. Save this as ttft.py: it streams one request and times every token.
        # ttft.py: time to first token and inter-token latency on any OpenAI-compatible server
# usage: MODEL=<name> python3 ttft.py <url> [prompt-file]
import json, os, sys, time, urllib.request
url = sys.argv[1] if len(sys.argv) > 1 else "http://localhost:8080/v1/chat/completions"
prompt = open(sys.argv[2]).read() if len(sys.argv) > 2 else "Explain the KV cache in three sentences."
body = json.dumps({"model": os.environ.get("MODEL", "local"), "max_tokens": 200, "stream": True,
                   "messages": [{"role": "user", "content": prompt}]}).encode()
req = urllib.request.Request(url, body, {"Content-Type": "application/json"})
t0, stamps = time.perf_counter(), []
with urllib.request.urlopen(req) as resp:
    for raw in resp:
        line = raw.decode().strip()
        if not line.startswith("data:") or line.endswith("[DONE]"):
            continue
        choices = json.loads(line[5:]).get("choices") or [{}]
        if choices[0].get("delta", {}).get("content"):
            stamps.append(time.perf_counter())
gaps = [b - a for a, b in zip(stamps, stamps[1:])]
print(f"TTFT {1000 * (stamps[0] - t0):.0f} ms | {len(stamps)} chunks | "
      f"mean ITL {1000 * sum(gaps) / max(len(gaps), 1):.1f} ms | "
      f"decode {len(gaps) / max(stamps[-1] - stamps[0], 1e-9):.1f} tok/s")
      2. Run it with a short prompt, then with a long one (paste about 3,000 words into long.txt).
        python3 ttft.py
python3 ttft.py http://localhost:8080/v1/chat/completions long.txt
      3. Cross-check with llama-bench, pointing -m at the GGUF that llama-server downloaded (under ~/Library/Caches/llama.cpp). It reports prompt processing (pp) and token generation (tg) speeds separately.
        llama-bench -m <path-to>.gguf -p 512,4096 -n 128

      Done when A two-row table: short vs long prompt, with time to first token and decode tok/s. You can explain why time to first token grew and decode speed didn't.

      Lab 5Benchmark until the GPU breaks2 h
      12 · Benchmarking & cost

      Find the load where latency stops meeting your target. This is the number that sizes the hardware.

      1. Set a target first, for example: p99 time to first token under 1 s and p99 inter-token latency under 60 ms.
      2. Sweep the request rate with vLLM's built-in benchmark, saving each run.
        for R in 1 2 4 8 16 32; do
  vllm bench serve --model Qwen/Qwen2.5-7B-Instruct --dataset-name random \
    --random-input-len 1024 --random-output-len 256 --num-prompts 300 --request-rate $R \
    --percentile-metrics ttft,tpot,itl --metric-percentiles 50,99 --save-result
done
      3. Plot request rate against p99 latency and throughput. Mark the knee where p99 crosses your target.

      Done when A latency–throughput chart with the knee marked, and the highest request rate that still meets your target.

      Lab 11Capstone: the cost memohalf a day
      12 · Benchmarking & cost

      Turn every lab into the one-page decision a bank's management actually needs.

      1. Cost per million output tokens = GPU cost per hour ÷ (output tokens per second at your target × 3,600) × 1,000,000. For example, a $2/hour GPU sustaining 1,500 tok/s costs about $0.37 per million tokens.
      2. For owned hardware, use purchase price ÷ (36 months × 730 hours) plus power and hosting as the hourly cost.
      3. Write the memo: workload and target, chosen model and format, measured curve, GPUs needed with failure headroom, cost per million tokens vs a cloud API at equal quality, and the risks.

      Done when A memo you could hand to a CTO, with every number traceable to one of your labs.
